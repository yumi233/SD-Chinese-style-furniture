## 问题与修复

以下全部修复在 `a4d592a`。每类均有 `test/v3Browser.test.js` 中的行为回归；简繁另外有 `test/locale.test.js`。

| 编号 | 现象与复现 | 原因 | 定向修复 | 修复后验证 |
| --- | --- | --- | --- | --- |
| Q01 | 完成生成后，从首页输入新家具描述进入工作台；描述被旧任务覆盖，按钮变成“修改 vN” | `restoreWorkspace` 无条件采用本地保存的已完成任务 | 新描述优先于终态任务；清空该任务指针、旧版本选择和设计记忆。运行中/提交结果不确定的任务仍先恢复 | 两端先完成任务再带新 prompt 进入；新描述、新作品、不带 parentId；另验证运行中恢复优先级 |
| Q02 | iPhone 点击设置/作品/账号后按 Esc，焦点回到 body；后续键盘操作丢失位置 | WebKit 指针点击按钮不必赋予焦点，原先只依赖原生 dialog 的“先前焦点” | `openDialog` 明确记录实际打开控件；关闭时检查控件仍存在、没有其他弹窗，再恢复焦点 | 两端设置/作品/账号/对比/模型设置逐个验证实际 activeElement；区域使用同一辅助函数 |
| Q03 | 切繁体后首页部分按钮、登录页、工作台设置和动态卡片仍混有简体 | 旧版静态映射未覆盖 v3；新生成节点没有参与语言切换 | 产品文案显式标记，局部转换与原文恢复；动态消息和选项同步；排除用户输入、名字、标题、模型内容 | 两端切换来回、刷新/跨页、动态卡片与模型选项；单测检查用户内容不变 |
| Q04 | 夜间登录主视觉仍大面积亮白，品牌与第二行标题几乎看不见；首页同样高亮 | 固定浅色素材沿用日间背景，但文字使用夜间浅色 token | 仅夜间暗化两页主视觉，标题用既有夜间 ink/olive；日间素材、布局、字体不变 | 日/夜截图比较；最亮背景计算文字对比度均 ≥4.5，最低约 5.06 |
| Q05 | 手机端主题、语言、新作品、居中操作都随桌面工具栏隐藏，没有替代入口 | 移动 CSS 隐藏按钮后未提供可访问操作 | 在现有设置弹窗内添加手机专用操作，复用现有状态和视觉样式；任务进行中禁用新作品 | 两端回归，手机从设置切主题/语言、开始新作品；不挤占主画布 |
| Q06 | 手机仍持续运行桌面 ASCII 漂移、放大镜和涟漪，未按任务要求降级 | 首页只按宽度换裁切，未按指针能力选择实时增强 | 只有精细指针且可悬停、未要求减少动态效果时启用实时增强；其他场景保留原预渲染 ASCII | 两端检查 canvas 存在/不存在；减少动态效果时无实时画布；桌面保留放大镜 |
| Q07 | 40 字用户名使手机右侧导航宽度约 712px，导出落到 x≈811px、无法点击 | 账号按钮宽度不受限，右侧导航禁止收缩 | 账号按钮设置最大宽度与省略，移动右侧导航允许收缩 | 临时账号真实保存 40 字名字；两端断言导出在视口内且中心命中按钮 |
| Q08 | WebKit 打开风格列表后 Tab 跳回画布，Shift+Tab 不回上一控件 | 隐藏当前获焦的 option 后，WebKit 丢失列表相对于页面的 Tab 位置；其默认导航还跳过按钮 | Tab 关闭列表后，从触发器计算同一弹窗/文档中下一个可见、启用控件；反向同理 | 两端 Tab 到“设置”，Shift+Tab 到“迭代”；Esc 只关列表，焦点回触发器 |

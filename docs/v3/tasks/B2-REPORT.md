# B2 报告 · 基于父图修改

负责人完成。

## 改了什么
- **前端**：「改一处」除了文字描述，还发送框选的归一化坐标 `region: { x, y, width, height }`（0–1，相对上一版图片）；「再来一版」沿用原任务的区域。
- **任务接口**（`src/generationTasks.js`）：校验 `region`（有限数、0–1、面积大于 0、不越界、必须和 `parentId` 一起出现）；由 `parentId` 读取当前用户自己记录的第一张图（只读私有图片目录内的 png/jpg/webp，≤5 MB）。引擎不支持或图片缺失时返回 400，**不会退回纯文字生成**。图片字节只放在内存里交给本次任务，不写进任务文件。
- **网关**：每次生成（含迭代的每一轮）把上一版图片作为 `referenceImages` 交给 provider；`region` 在请求规范化后保留下来。`listEngines().parentEngines` 列出支持的引擎。
- **Codex**：提示包区分「要修改的上一版」和普通参考，写明保持构图、视角、背景、光线、材质和未提及的部件，只改描述里的地方；有区域时写出百分比坐标。仍沿用「输出与输入相同则排除」的检查。
- **兼容图像接口**：带上一版时改用 OpenAI 兼容的 `/images/edits`（multipart 上传图片），提示里写明区域。
- **历史记录**：新记录保存 `region`。

## 验证
- `make check`（含桌面 Chromium 与 iPhone WebKit）：**141 项通过，0 失败，0 跳过**。
- 新增：父图字节到达每一次生成调用（单次与迭代每轮）、任务文件不含图片字节、区域取整并存进历史；不支持的引擎、无图记录、路径穿越、各类非法区域被拒；Codex 提示包与 `/images/edits` 的请求内容；浏览器里「改一处」请求带区域、模拟服务收到上一版图片与区域指示。

## 限制
- 区域是给模型的指示，不是像素级蒙版；模型仍可能改动框外。
- A1111、ComfyUI 暂不支持基于上一版修改。

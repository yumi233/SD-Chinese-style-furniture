## 任务与恢复

- 统一调用 `/api/v1/generation-tasks` 的 POST、GET、详情及停止接口；初始化通过 GET 恢复服务端进行中的任务。本地仅按账号保存末次任务指针和作品标题／设计记忆，演示数据使用独立命名空间。
- 任务按后端 `queued / running / completed / failed` 和 `preparing / generating / reviewing / saving` 呈现；轮询中的部分结果立即展示，未评审和评审失败不编造分数。
- 页面刷新不会自动创建第二个生成任务。网络异常保留任务并重连；若提交响应丢失，会查询活动任务，并在必要时使用原始请求和同一个 `requestId` 找回已完成任务，利用后端幂等性避免重复调用模型。
- 账号切换／退出会中止旧请求，并用会话代次拒绝迟到的私有结果；清空画布、历史、评审和比较图片。删除历史时清除对应末次任务指针；恢复时以当前历史为准，不从旧任务快照复活已删除记录。
- 当前后端每个迭代任务共用一条历史 ID，卡片采用独立的本地轮次 key；提交 `parentId` 始终使用历史 ID。跨记录连线接到父历史的最佳轮，缺少最佳轮信息时接到最后一轮。后端没有保存“选中了父历史的哪一轮”的独立字段。

## 八类演示状态

`/studio?demo=<状态>` 不发送真实 API 请求，也不写入真实账号或历史。预置状态每次打开重新初始化；用户在演示中主动提交后可刷新继续其模拟任务。

## 已知边界

1. **无法实现即时取消当前模型请求**：现有后端的单次任务不支持取消；迭代停止只会设置 `stopRequested`，当前轮完成后不再开始后续轮次。界面始终允许发起停止操作，并如实说明这一限制；不会伪装已取消当前请求。本任务禁止修改后端，故“随时停止”无法解释为立即中断服务端生图。
2. 后端没有返回扣费／退款信息，失败界面不会声称「这次没有扣次数」。普通单次结果没有视觉评分，显示「未评审」。框选是文本引导，设计记忆也是提示词约束，均不保证像素级保持。
3. 本次验收使用本地模拟模型，证明真实应用链路及交互，不代表任何外部付费模型、画质或家具工程结构已经验收。没有进行 Safari、Firefox 和实体手机触摸验证；跨域外部图片若不允许 CORS，会明确报告导出失败，正常持久化的同源历史图片已实测下载。
4. 作品名和设计记忆目前按账号／版本树保存在浏览器中，跨设备仍使用后端历史标题；后端没有作品标题或设计记忆的独立写入接口。切换父轮时也只能以真实历史 ID 建立跨记录关联。
5. Docker 技术配置无需变化：既有 `COPY . .` 已包含新的前端模块和页面，启动、依赖、端口、持久化均未改变。未构建或发布镜像。`RELEASE_RULES.md` 对静态资源要求同步更新 Docker 文件／文档，而 T5 的允许列表不包含这些文件；本次遵守 T5 范围，合并发布时需由负责人协调这一文字要求。

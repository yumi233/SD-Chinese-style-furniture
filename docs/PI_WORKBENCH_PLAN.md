# 木生工作站后续整体方案

日期：2026-10-29。状态：实施提案，尚未集成 Pi。

依据：[用户分享的盘点](https://share.onorca.dev/a/tFZSNz9HxyuR)、当前源码 37d038a9bde664fba48afccd13d276c17f9451db，以及 [Pi 官方 SDK 文档](https://pi.dev/docs/latest/sdk)。分享文件是范围依据，其中的历史测试结果不是本轮验证结果。

## 1. 产品目标

把一次性的家具生图流程推进为可以持续修改、比较与追溯的设计工作台。用户围绕一件家具开展设计，在同一会话中描述需求、查看图片、提出修改、比较版本，最后导出图片及设计说明。Pi 负责工具编排，现有 Provider 负责生成和视觉评审。

第一版以“设计会话”为核心，不同时建设团队项目管理、CAD、三维建模、商城或外部知识库。项目实体在确有多家具系列管理需求后再增加。

典型路径：新建设计 → 描述用途与造型 → 必要时补充关键约束 → 生成首版 → 针对选中版本修改 → 比较并选定 → 导出。普通生成继续可用；会话能力逐步接入。

## 3. 第一版范围与界面结构

沿用当前视觉资产与变量。主区域展示家具图，侧区承载设计对话，下方提供版本缩略图；会话列表可折叠，高级参数收进设置。窄屏以图片和对话切换呈现，避免同时压缩三栏。

默认主动作随状态变化：未生成时“开始生成”，选中版本后“继续修改”，运行时“停止”。下载和比较作为次级动作。仅在缺少影响结果的尺寸、用途或参考主体时提问，避免每轮重复填写表单。

遵守 AGENTS.md 新增原则：Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.

去掉重复的中英文眉题、卡片说明、已被标题表达的副标题；保留输入标签、错误原因、任务状态和必要的费用信息。模型供应商、工具参数、运行日志置于详情，默认画面围绕家具结果与下一步动作。

必须覆盖空态、生成中、已有部分结果、成功、失败、停止、断线、刷新恢复八类状态。评审建议按比例、材质、风格与需求符合度展示具体问题，分数不占据主视觉。

## 4. 技术结构

浏览器 → Express 认证/API → GenerationTasks 任务外壳 → AgentRuntime 接口 → PiAdapter → 受限业务工具 → 现有图片、视觉、案例与历史模块。

建议新增 src/agent/runtime.js、piAdapter.js、toolRegistry.js、policy.js，以及 src/designSessionStore.js；按已有职责拆分，避免提前建立复杂框架。前端新增会话、版本、事件模块，逐步从 studio.js 移出对应逻辑。

旧编排通过 runtime 选择开关继续可用，默认仍为旧路径；失败时显示可恢复结果，不自动跨引擎重试付费调用。SDK 模块制式若与 CommonJS 不兼容，优先评估独立 ESM 适配模块或进程边界，不做全仓模块迁移。

官方文档目前显示包名为 @earendil-works/pi-coding-agent，并支持会话、事件订阅和显式资源/工具配置。实施时必须核实目标版本、包来源、Node 要求、许可证及锁文件；历史 @mariozechner 包名不能直接当作当前安装指令。网页最新文档也不能证明本机已安装或兼容。

## 5. Pi 工具与执行边界

| 工具 | 输入与输出 | 服务端约束 |
| --- | --- | --- |
| read_design_context | 当前需求、已选版本、必要消息 | 账号和会话由服务端绑定 |
| search_reference_cases | 关键词 → 内置案例 | 标明来源，不伪称联网检索 |
| generate_image | 设计要求、尺寸、版本引用 → 图片资产 | 参数校验、调用额度、幂等记录 |
| evaluate_image | 本会话图片 → 结构化建议 | 仅视觉建议，失败仍保留图片 |
| save_design_version | 已生成资产与摘要 → 版本记录 | 禁止写任意路径、禁止覆盖旧版 |

不开放默认 shell、任意文件工具、自动发现的个人扩展或全局凭据。工具列表、模型、资源加载和数据根目录全部显式配置；启动时检查实际激活工具。提示词只能补充约束，权限和额度必须由代码强制执行。

首版默认最多三轮生成，另设总工具调用数、超时和输出限制。记录实际用量；供应商不提供费用时标记未知，不伪造精确账单。费用估算与实际费用分开存储。

## 6. 数据与接口

新增 DesignSession：id、ownerId、title、brief、selectedVersionId、runtimeSessionRef、schemaVersion、timestamps。
新增 DesignVersion：id、sessionId、parentVersionId、taskId、assetIds、promptSnapshot、parameterSnapshot、evaluation、createdAt。
新增 TaskEvent：taskId、seq、type、safePayload、createdAt；模型上下文与面向用户的事件分别保存，避免将内部信息直接流到浏览器。

第一版继续单进程文件存储，原子写入并为同一会话串行化写入；会话索引失效时可从记录重建。历史保留原格式，采用关联索引按需接入；无 owner 数据不得自动归给当前用户。Pi 会话记录单独存放在私有目录，由业务会话映射，不能拿旧生图历史冒充完整对话。

建议新增 /api/v1/design-sessions 列表/创建、/:id 读取、/:id/messages 提交消息、/:id/versions 列表、/:id/selected-version 选择版本。所有读取和写入均校验归属。复用 generation-tasks 查询/停止，先通过带 afterSeq 的增量轮询传递事件；有明确体验需求后再加 SSE，避免双套状态来源。

## 7. 去重、停止和恢复

提交业务动作时先持久化 requestId、toolCallId、参数摘要和提交意图，再调用 Provider，记录外部请求 ID 与结果。供应商支持幂等键时传递同一键；提交超时或进程崩溃导致结果未知时，进入待核实状态，不能直接重放生成。

点击停止立即阻断后续工具调用。外部任务支持取消时发起取消；不支持时显示已停止后续步骤、当前外部生成仍待返回，并收存迟到结果。已有图片始终保留。

刷新重连恢复业务状态与事件，不重新提交消息。重启后可恢复已完成会话上下文；未决外部请求先查询或人工核实。第一版不承诺跨重启自动续跑付费步骤。前端断线不等于任务取消。

## 8. 分阶段交付

| 阶段 | 交付内容 | 通过条件 |
| --- | --- | --- |
| A 基线校正 | 更新架构/API说明，记录当前回归与部署条件 | 文档与源码一致，现有测试通过 |
| B 内核验证 | 固定依赖、PiAdapter、工具白名单、mock事件 | 不访问真实模型即可验证工具事件与生命周期；默认工具确实关闭 |
| C 生成闭环 | 生图、评审、保存接入，停止与提交台账 | 成功、超时、重复提交、评审失败均不丢图或重复生成 |
| D 设计会话 | 需求持续修改、版本分支、历史关联、刷新恢复 | 双账号隔离，重启与旧历史兼容通过 |
| E 界面整合 | 图片主区、对话、版本比较与响应式 | 浏览器实际走通主要流程及八类状态 |
| F 发布验收 | 指定真实模型联调、镜像、说明、备份与回退 | 用户确认模型及费用范围后实测；旧镜像与旧数据可恢复 |

每阶段作为可独立审阅的变更交付。A→B→C 为主依赖链；数据契约在 B 前确定，D 接入后再完成 E。首个可用里程碑是 C：能通过受限 Pi 编排生成、评审并保留结果；完整第一版到 F。

## 9. 验收与回退

自动测试覆盖跨账号会话/资产访问、重复消息、未知外部结果、停止竞态、迟到图片、重启恢复、事件顺序和旧历史读取；使用 mock 与临时目录。全套项目检查通过后做浏览器实际操作，真实模型联调另记图片、调用数、耗时、费用来源和取消能力。

运行依赖或配置改变时同步 Docker、Compose、安装及发布文档。先备份数据和配置，保留旧镜像摘要；新会话数据写在独立目录，旧数据采用兼容读取，避免回退要求逆向转换。关闭 Pi 开关后仍能访问旧生成流程及历史；新会话暂时只读也需明确显示。

## 10. 后续扩展顺序

第一版稳定后，优先建设参考图上传与管理，再做系列家具项目和设计说明导出；真正出现多用户并发瓶颈后引入数据库、队列与多实例部署。参考图编辑需先验证所选 Provider 的实际能力，不能把图片附件当作已实现保真编辑。

本轮交付为规则变更与整体方案；没有安装 Pi、委派模型、调用付费生成、修改生产或发布。下一步推荐执行 A 与 B，先解决兼容性和工具隔离，再改用户工作流。

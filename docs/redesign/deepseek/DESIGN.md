# 木生 · 构序台

## 一句话

**构序台**把家具当作可追踪、可拆解、可重组的数字构件来设计，而不是把一句话换成一张图。

它年轻、超前的地方不在于使用更亮的颜色，而在于把 AI 设计过程本身做成界面：一句话先变成可操作的样件，等待过程被拆成真实阶段，修改被收束到一个局部，每次结果都带着评审、记忆和版本关系继续向前。

## 设计判断

- **唯一主角**：作品本身。主页主角是活的家具样件，工作台主角是画布里的家具，评分和参数都贴着作品后退。
- **唯一主动作**：把一句意图变成下一版。主页用“进入工作台”，工作台用“开始构序 / 生成修改版”承接。
- **删减**：不做传统官网的大段功能说明、后台式侧栏导航、数字堆叠仪表盘、眉题、面板角标、英文括注、解释性小字和互相抢注意力的多个主按钮。
- **保留**：作品名、当前版本、素材和尺寸、评审六维、下一步建议、生成与停止、历史、比较、导出。这些信息会直接决定用户是否继续迭代。
- **调性**：活跃但克制，精密但可玩，轻量与中等信息密度并存。暖纸色承接家具材料，黑色工程线建立仪器感，橙色负责动作和风险，酸性黄绿负责已确定的选择与成功反馈。
- **视觉参照与取舍**：不引用仓库里的现有页面。只吸收创作工具常见的“对象中心”结构：把导航让给对象、让状态与动作贴近对象；不沿用后台左侧菜单、全屏卡片网格或大面积深色 AI 面板。
- **交互参照与取舍**：借鉴设计工具中“画布 + 版本历史 + 属性面板”的成熟操作逻辑；主页改成一进入就能改变家具的实时样件，而不是静态宣传图。等待、停止、失败、刷新恢复都围绕同一件作品显形。

## 信息架构

### 公共站点

1. **首页**：品牌入口、实时样件、需求输入、工作方法、样本、登录入口。
2. **登录 Sheet**：邮箱输入；登录完成后进入工作台。真实接入后，首次点击“开始构序”若未登录，先展示该 Sheet，同时保留用户草稿，不让登录打断创作。
3. **工作台**：独立应用页面，可从首页带描述、风格和显示模式进入。

### 工作台内的视图

- **空画布**：只显示纸面、中央状态和底部输入；版本栏、评审栏和画布工具全部收起。
- **生成过程**：理解需求 → 起稿 → 出图 → 评审，支持停止。
- **作品工作区**：画布、版本时间线、评审/参数面板、底部需求与修改输入。
- **版本比较**：并排或叠影比较两版。
- **历史作品**：最近作品集合，可回到任意作品。
- **导出评审页**：一张可下载的 PNG，包含主图、评分、材质和说明。
- **账户 Sheet**：登录状态与同步提示。

这些视图使用同一套视觉和状态语言，不需要在多个页面间跳转。主页面只负责建立意图和信任；真正的持续设计留在工作台。

## 关键流程

### 首次进入

首页直接出现可改变的家具样件。用户输入描述，或选择“明式 / 新中式 / 宋韵 / 禅意”，样件立刻换成对应对象与骨架；点击“进入工作台”后，描述、风格、类型、ASCII/Dither 参数一并带入。

真实产品中，此时若未登录，先出现登录 Sheet。登录按钮和关闭按钮同时可见，关闭不丢弃输入。

### 第一次生成

工作台显示空画布和底部输入。提交后进入四段进度：

1. 理解需求：锁定对象、材质、使用场景。
2. 起稿：显示低保真草稿，画布以 Dither 预览，明确告知“草稿 01”。
3. 出图：完成效果图，保持当前视图。
4. 评审：出现六维分数与“下一步”。

进度不是假转圈。每一段都有当前阶段、已完成、等待三种文字与颜色状态，用户可随时“停止”。停止后明确写出“没有生成新版本，输入和锁定项都还在”。

### 评审 → 修改 → 比较

1. 结果先在画布上出现，评分随后进入右侧。
2. 用户可输入整段修改意见，也可切换“框选”拖出局部，再输入“扶手再薄一点”。
3. 提交后生成新版本，旧版不被覆盖；时间线自动选中新版。
4. 新版评分、建议、锁定项同步更新。
5. “比较版本”打开旧版/新版并排对照；切换“叠影”后出现可拖动分界线。
6. “导出”生成单页评审版式，用户可下载 PNG。

### 回到历史

工作台顶部“历史作品”打开最近作品 Sheet。每个卡片都是一个真实生成版本的缩略图，带作品名、时间、材质、风格、综合分。点选后恢复该作品的主图、评审和后续输入。当前浏览器还会把版本、锁定项和界面参数保存在本机；刷新时自动恢复。

## 核心界面

### 主页

桌面为不对称双栏：左侧是“一句话，长出 / 一件家具”的三行展示字和需求输入，右侧是活的样件仪器。样件占据首屏最大视觉重量，输入框和主按钮紧贴它。

交互：

- 输入描述会推断椅、桌、柜、凳，并即时换图。
- 椅 / 桌 / 柜 / 凳切换只换对象，不换页面。
- 实体 / ASCII / Dither 切换显示模式，格距滑杆直接改变样件纹理。
- 点击样件或“换一种骨架”产生新 seed，给用户“可以玩”的第一印象。
- 风格 chip 会同步更新样式，并把选择带入工作台。

首屏下方用同一套数字编码解释方法：说清楚 → 看它长出来 → 只改一处 → 留下判断。样本区不是通用商品卡，而是三个具体作品和评分。

### 工作台

桌面 1440 视口的骨架是：

- 64–68px 顶栏：品牌、作品名、保存状态、历史、比较、导出、账户。
- 空态没有版本栏和评审栏，画布占满工作区，只在底部保留一句描述和“开始构序”。
- 第一版生成后，224px 版本时间线才出现：版本数、缩略图、分数、当前版本和新建方向。
- 中央画布：工具栏、纸张画板、缩放、局部选框、底部需求 Dock。
- 354px 右侧检验面板：综合分、六维评分、下一步、锁定项；可切到构序参数。

它避免传统后台的“左侧功能菜单 + 卡片仪表盘”，空态尤其只留下画布与输入。所有面板都是工具，不是内容列表；评分永远不与主图争同一重量。工作台不再显示“首版描述”“未锁定属性”“空白画布 / 100%”等重复状态，缩放只保留在画布控制里。

### 生成过程

生成面板以浮层落在画布中央，不遮挡底部输入。右侧始终可停止，四段进度只保留工序名和“等待 / 进行中 / 完成”，不重复解释每一步做什么。进度在 58% 时先给出草稿图像，让等待有可观察结果。评审阶段完成后面板收起，版本与评分从两侧接入。

### 画布

- 滚轮或 `+ / −` 缩放，`适配`按当前视口重新居中。
- 抓手工具、按住空格拖动、或直接拖动画布外背景可平移。
- 框选工具拖出矩形后出现四角把手、实际毫米尺寸和“已框选局部”浮条。
- 底部输入会把选区作为版本元数据写入新版本；不承诺像素级重绘，界面只说“局部”。
- Canvas 可通过 Tab 聚焦，按 `S` 建立可键盘操作的默认局部选框；之后输入修改意见并提交。
- 画板以真实纸张、网格、尺寸和登记标记构成“设计图纸”，但对象本身由代码生成的几何家具组成，不使用照片。

### 评审

右侧顶部是综合分，下方六条细线分别表示文化准确、结构合理、材料工艺、设计创新、场景适配、AI 使用。低于 82 的条目使用橙线，代表下一轮优先处理，而不是把作品变红。综合分、当前判断和一句“下一步”组成结论；详细解释按需阅读，不压过画布。

设计记忆放在评审下方：白蜡木、坐深 560、靠背弧度、不加重扶手。默认不锁定，点击后变成橙点锁定状态；下一版继续保留这些属性。

### 版本与比较

每个版本以“缩略图 + V01 / 风格 + 分数”出现，当前版本使用黑框，最佳版本有黄绿点。版本不会在时间线上被覆盖。没有版本时整栏不存在。

比较 Sheet 支持：

- 通过两个下拉框选任意两版。
- 并排看形体、缩略图、分数。
- 叠影拖动看新旧交界。
- 下方列出三条设计差异：扶手厚度、靠背过渡、锁定项。

### 历史与登录

历史是覆盖在工作台上的 Sheet，而不是离开当前任务的页面。打开后仍能看出背后是刚才的画布；点击卡片即恢复。登录使用简单表单 Sheet，不引入第三方品牌或复杂注册步骤。

### 移动端

390px 下不是把三栏压小：

- 顶栏只保留品牌、作品名、菜单。
- 空态不显示版本条、评审栏、框选工具栏或百分比缩放，作品画布先占满可用空间。
- 输入 Dock 固定在视口底部，文本域与主动作保持同一行；生成后上方出现“版本 / 评审”切换。
- 版本与评审都从底部抽屉出现，不再纵向占用首屏；版本抽屉按内容高度展开，评审抽屉内部滚动。“比较 / 导出”固定在抽屉底部并完整可见。
- 画布仍可框选、抓手和平移；缩放只保留 `− / +`，不显示奇怪的适配百分比。

## 视觉系统

### 颜色

| Token | 值 | 用途 |
| --- | --- | --- |
| `--paper` | `#f3f0e5` | 主背景、作品纸面、工具画布 |
| `--paper-bright` | `#fbf9f1` | Sheet、输入、需要从背景浮起的内容 |
| `--paper-deep` | `#e7e2d4` | 弱分组、骨架底板 |
| `--ink` | `#191c18` | 主文字、主按钮、工程线 |
| `--muted-strong` | `#51544c` | 辅助正文、状态、数据标签 |
| `--signal` | `#e0522b` | 主动作、局部选框、下一步、最低评分 |
| `--lime` | `#c8f05a` | 已经确认的选择、成功、锁定记忆 |
| `--blue` | `#465fc7` | 键盘焦点，不用作品牌色 |
| `--success` | `#3d773f` | 已完成阶段 |
| `--danger` | `#a93122` | 失败与停止 |

黑色是结构，橙色是操作，黄绿色是“记住并确认”。颜色不作为唯一状态信号，所有状态同时有文字或形状。

### 字体

- 展示：`Avenir Next Condensed / DIN Condensed / PingFang SC`，粗体、紧字距，承担标题和结论。
- 正文与操作：`Avenir Next / Futura / PingFang SC / Hiragino Sans GB`，正常字重，中文优先。
- 编号和参数：`SFMono-Regular / Menlo / Cascadia Mono`，用于版本、坐标、时间、尺寸与数据。
- 所有正文角色保持 12–18px；高密度工具的小字只用于版本元数据，不用于任务说明或错误文本。

### 间距

只使用 4px 网格：

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64 / 80`

- 4：标签与点、小控件内部。
- 8：面板内边距、控件组间距。
- 12：同组信息的行距。
- 16：卡片/输入的基础内边距。
- 24–32：面板与区块开始。
- 40–80：主页章节的呼吸区。

### 圆角与嵌套

半径 token：

| Token | 值 | 层级 |
| --- | --- | --- |
| `--radius-dialog` | 32px | 顶层 Dialog / Sheet / 大底色区 |
| `--radius-shell` | 24px | 仪器、主页大色块、作品卡外壳 |
| `--radius-panel` | 16px | 面板、卡片内层、输入区 |
| `--radius-control` | 8px | 按钮、输入、滑块周边、局部工具 |
| `--radius-chip` | 4px | 标签、极小控件、工程标记 |
| `--radius-pill` | 999px | 胶囊和圆形控件 |

所有盒子使用同一圆心关系：`内圆角 = 外圆角 − 内边距`。

- Dialog 32px，内边距 16px → 内部卡片/输入 16px。
- 仪器/作品卡 24px，内边距 8px → 内部面板 16px。
- 面板 16px，内边距 8px → 内部按钮/缩略图 8px。
- 控件 8px，内边距 4px → 内部标签 4px。
- 最小圆角 4px；胶囊和圆形保持全圆。

实现里以 `--radius-*` 和 4px 间距 token 为唯一来源。`@supports (corner-shape: superellipse(1.25))` 打开连续曲率圆角，所有胶囊、圆形、状态条显式设置 `corner-shape: round`。不支持 `corner-shape` 的浏览器回退到普通圆角，布局不变。

### 动效

- **主操作**：按钮按下 80–150ms 缩到 0.96–0.98，生成按钮结束后把当前位置交还给结果面板。
- **状态切换**：生成阶段使用一条橙色进度线依次走过四站；面板出现 260ms，停留在画布上方而不跳页。
- **首次进入**：主页标题先出现，说明随后 80ms 跟上，样件最后一个进入；总时长不超过 1.4 秒。
- **画布**：缩放/平移为 220ms 的阻尼感过渡；直接拖动时取消过渡，保证跟手。
- **比较**：并排到叠影只改变画面容器和交界线，不做两页交叉淡化。
- **减少动态效果**：`prefers-reduced-motion: reduce` 下关闭入场、扫描、呼吸点与进度流动，直接显示最终状态。

## 两条指定方案的落实

### 递进式圆角 + 连续曲率

主页需求卡片、工作台 Sheet、历史卡、比较弹窗、导出弹窗都按“外层大、内层小、差值等于 padding”的实现。最典型的是导出 Sheet：32px 外框 + 16px 内边距，里面是 16px 的主图卡；版本卡则是 16px 外框 + 8px 内边距 + 8px 缩略图。所有值来自 CSS token，没有散落的随机圆角。

### ASCII / Dither 参数化

主页右侧样件默认是 ASCII，格距 12、对比 88；用户可即时切换到实体或 Dither。字符渲染先按饱和度与明度筛出家具体积，再用非线性暗度映射压入更密的字符，因此沙发面、椅腿和靠背都能读出完整轮廓，而不是只有稀疏勾边。

工作台“构序参数”面板提供同一套三个参数；格距滑杆从 4 到 24 改变字符格或像素块大小。

- 格距：ASCII 的字符采样格，Dither 的像素块。
- 对比：把明暗对比压缩到可读的层级。
- 纵向遮罩：ASCII 默认 90、Dither 默认 88，越往下越像扫描纹理而不是均匀噪点。

效果只改变画面的表达方式，不把家具变成实体材质照片；结构线、木色块和尺寸线仍然可辨认。手机上默认格距比桌面更大，保证字符/像素格眼能看清，而不是变成一层几乎不可见的滤镜。

## 八类状态

| 状态 | 画面表现 | 用户可做的下一步 |
| --- | --- | --- |
| 空态 | 空纸面、登记线、中央“画布还空着” | 下方输入第一句 |
| 生成中 | 中央四段工序、橙色进度线、停止按钮 | 观察阶段或停止 |
| 部分结果 | 58% 后出现低对比草稿、Dither 预览和“草稿 01”标记 | 继续等待或停止；旧版本仍保留 |
| 成功 | 主图清晰、六维评分出现、版本卡新增、锁定项可见 | 改一处、比较、导出、回历史 |
| 失败 | 画布下方浮出失败状态，明确“未扣次数，输入仍在” | 重新开始，输入不丢 |
| 已停止 | 青绿色停止状态条，说明“没有生成新版本” | 继续修改，旧画布恢复 |
| 断线 | 顶栏下方出现“网络已断开”，保存状态变为离线；生成中到下一阶段即停 | 恢复网络后继续，已有版本可读 |
| 刷新恢复 | 保存的 `wasGenerating` 被识别，出现“上次生成已中断，已恢复最近保存的版本” | 继续修改或重新开始 |

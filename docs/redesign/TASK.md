# 设计任务：交付一个完整的 UI / UX 方案

先完整阅读 `docs/redesign/BRIEF.md`。你是独立设计师，另有三位设计师在做同一题目，互相看不到。你的方案代号写在文末，下文用 `<代号>` 表示。

## 你要交付的

1. **设计说明** `docs/redesign/<代号>/DESIGN.md`
   - 一句话设计理念与名字；为什么它是年轻化、超前化的。
   - 信息架构：有哪些页面 / 视图，它们怎么连起来。
   - 关键流程：首次进入 → 第一次生成 → 评审 → 修改 → 比较 → 导出；以及回到历史作品。
   - 每个核心界面的布局与交互说明：主页、工作台、生成过程、画布、评审、版本与比较、历史、登录、移动端。
   - 视觉系统：颜色、字体、间距、圆角 token（写出完整的嵌套关系）、动效原则与时长。
   - 两条指定方案（BRIEF 第 5 节）具体用在哪里、怎么用。
   - 八类状态各自的表现。
2. **可点击的原型**，全部放在 `public/proposals/<代号>/` 下：
   - `index.html`：主页（应用官网），必须有可上手的交互。
   - `studio.html`：工作台，必须能实际操作：输入描述 → 点击生成 → 看到分阶段的生成过程 → 出现结果与评审 → 至少能做一次「修改」或「框选改一处」并产生新版本 → 版本比较。画布可缩放、平移。
   - 样式与脚本放在同一目录下（如 `style.css`、`app.js`），用相对路径引用。
   - 使用模拟数据，不调用付费接口，不依赖登录。家具画面用代码生成（Canvas / SVG），不要使用 `public/assets` 里的照片。
   - 桌面 1440 与手机 390 都要完整可用。
3. 在 `docs/redesign/<代号>/DESIGN.md` 末尾附「自检」：列出你验证过什么、还有哪些不足。

## 规则

- **只能新建或修改** `public/proposals/<代号>/` 与 `docs/redesign/<代号>/` 下的文件。不要改动仓库里任何其他文件，不要改后端，不要动 `package.json`。
- 不要阅读或参考 `public/` 下现有页面（`public/index.html`、`public/studio.html`、`public/css`、`public/js`、`public/ui`）。
- 不要安装依赖，不要联网下载资源。
- 完成后运行 `node --check` 检查你写的每个 JS 文件。
- 用一个 git 提交保存你的成果，提交信息以 `Add <代号> redesign proposal` 开头。
- 最后用中文回复：方案名称、核心理念（三句话以内）、文件清单、你认为最强的三个设计点、已知不足。

# 木生 · 形场

> 一件作品，一片不断生长的设计现场。

代号：astra。独立离线 UI/UX 提案；以本次 TASK 与 BRIEF 为唯一产品输入，不沿用现有页面或此前 Figma 方向。

## 方向与范围

面向设计学生、年轻设计师与小型工作室。主角是持续演进的一件家具，主动作是把一句需求变成可评审、可修改的版本。用数字网格、字符重组与钴蓝选区表达家具的可编辑性，不借古典装饰暗示中式。年轻感来自直接动手与鲜明排版；前瞻感来自图像、评审和设计记忆处在同一个工作现场。

主模型独立设计与自检，未调用子代理、模型 API、付费接口。未独立生成概念或独立评审。禁止下载依赖与参考资源，故不做外网参考拆解，不引入动效库。oil-ui 仅用于层级、减法、视觉与操作分开验收的方法，不复用其旧方案。

内部比较过三个结构：纯对话式易遮住作品；节点式增加学习成本；选定「图纸 + 侧边需求 + 版本底片」。删除营销数字、装饰英文眉题、仪表盘指标卡、常驻管理入口；参数与英文提示词折叠，状态消息只出现一处。

灰度结构：桌面主页为大字宣言 / 全幅家具数字实验 / 底部直接开始；桌面工作台为顶部作品导航 / 264px 需求栏 / 弹性画布 / 288px 评审栏 / 版本底片。手机为顶部作品导航 / 画布 / 需求、评审、版本三标签内容 / 生成主动作，不压缩三栏。

## 信息架构与关键流程

```text
主页 index.html
 ├─ 数字家具实验（Dither / ASCII / 原形）
 ├─ 输入一句话 → studio.html?prompt=… → 新作品
 └─ 我的作品 → 工作台中的作品集弹窗
工作台 studio.html
 ├─ 设计起点：描述、案例、风格、参数、提示词、记忆
 ├─ 画布：生成结果、缩放、平移、选区、批注
 ├─ 一起推敲：六维评审、建议、自由修改、同参数重跑
 ├─ 版本轨迹 → 任意版本 → 新分支 / 双版本比较
 ├─ 作品集 → 恢复 / 删除 / 新建
 ├─ 导出 → 作品页预览 → 作品页 PNG / 主图 PNG
 └─ 账号弹窗：登录 ↔ 注册 / 继续体验
```

首次进入不用注册：先在主页改变数字家具的表现，再带一句描述进入工作台。空画布只提示一个动作：写需求或用灵感起点。生成先理解需求、再起稿、再出图、最后评审；出图阶段就能看到部分结果，评审不会阻塞对画面的观察。

第一稿完成后右侧出现六个分数与一条主要建议。可以采纳建议、自由描述、同参数重跑，或者框选一个区域再修改。每一次修改生成新版本，原版本保留；在任意旧版上修改，父版本记录会明确显示分支来源；「回填这一版需求」恢复该版本的描述与参数，不立即生成。比较器可选择任意两版，显示形态、修改词、综合分差与结构分差，选择右侧版本继续推进。

满意后预览一页作品说明，下载 1200 × 1500 PNG；也可按所选 16:9 / 4:3 与 720 / 1080 输出透明背景主图 PNG。作品保存在浏览器 localStorage 中，可在作品集恢复，包括描述、参数、所有版本、选中的版本、批注、任务阶段。删除先显示作品名称与版本数量，再确认；不影响其他作品。

## 核心界面

### 主页

大字「让想法，长出下一版。」直接表达迭代价值。主视觉是可交互的程序化圈椅，保持家具识别度，又可拆成字符与像素块；没有旧家具照片、品牌背书、虚构用量。底部深色工具条是上手入口，描述输入紧随图像。中段只有「说出来 / 一起推敲 / 留下更好的」三个动作，尾部返回同一个工作台入口。

### 工作台

桌面顶部只保留品牌、作品名、作品集、导出与账号。作品名可重命名。左栏输入需求、选风格；精细参数折叠。中央始终是图纸和版本轨迹；右侧只在有评审后变为有效内容。新建、恢复、分支与生成不会覆盖旧版本。生成时锁定会改变任务含义的控件，允许缩放、平移和停止。

四种风格入口、全部比例与分辨率、精细度、氛围、约束条件、自动评审迭代目标分与 1–3 轮上限都有对应控件。默认目标 85、上限 2；不足目标且轮数未用完才继续。最佳版本在轨迹中标记，用户可恢复该版继续。管理员设置不在普通用户原型中暴露；正式应用仅在验证管理员身份后加入口。

英文提示词可查看、手动编辑并随版本快照保存。原型的默认英文为按家具类别组合的模板，不是真实翻译服务；生产集成需使用已有文本适配器。三个灵感起点填入圈椅、茶桌和边柜需求，不假称为完整案例库检索。

### 生成过程

四个有名称的阶段与一条短解释代替无限旋转。图像阶段先创建一个待评审版本，评审补齐同一版本，刷新后按任务 ID / candidate ID 接续，避免重复版本。自动迭代显示当前轮次。随时停止，保留已出的图与已有评分；继续会从同一阶段推进。

生产映射：阶段必须来自 `generation-tasks`，轮次与结果映射 `agent/run` 或任务结果，不能把原型的定时器当实际模型进度。真实扣费信息必须取后端结果，不能因网络错误就宣称免费。原型状态中明确标记演练未扣次数。

### 画布

浅灰点阵提供定位参照，作品位于中心。底部工具条固定在图纸内：平移 / 框选 / 批注 / 缩小 / 复位 / 放大。滚轮缩放，拖动平移，方向键平移，＋ / − 缩放，0 复位。手机单指拖动，使用工具按钮缩放；不要求用户发现隐形手势。

框选可拖出矩形，按钮也直接给出默认选区，让键盘用户无需拖动。选区下方出现一句话编辑器，提交后把选区坐标、当前缩放与平移、修改词记录到新版本；保留原稿。清楚提示局部边界不保证像素级一致。程序化绘图会调整相应家具的构件厚度 / 宽度，不是真实图像局部重绘。批注保存在所选版本，有编号标记与文字记录；目前标记为固定示意位置，不实现任意锚点。

### 评审

总分为安静的数字，不放在作品上方，也不用巨大雷达图抢走注意。六维为等宽细条与数值：文化准确性、结构合理性、材料工艺、设计创新、场景适配、AI 使用。建议描述改哪里与保留哪里，主动作是「采用建议，生成下一版」。高分后仍提醒打样前验证结构；视觉评审不承担工程结论。

### 版本与比较

底部版本底片显示缩略图、编号、分数、最佳标记和父版本。当前版本使用钴蓝边框，点击旧版本只切换查看，不修改其他版本。比较是大弹窗：桌面双图并排，手机上下排列，同一缩放规则；可任意选择两版，同版比较禁用继续操作。分数未完成时不计算虚假分差。

### 历史、账号与导出

作品集用标题、版本数与日期识别会话。恢复按钮明确回到工作台，不复制一份新会话。账号弹窗展示完整邮箱 / 密码、登录 / 注册切换、浏览器校验与跳过路径；不发送或保存任何凭据，不伪造已登录状态。生产环境首次生成再触发登录，并保留输入与目标操作。导出先预览，再下载，包含主图、材质、说明、版本与六维评分，标记原型数据来源。

### 移动端

390px 宽不保留缩小版三栏。顶部导航保留作品集与导出，账号压缩成头像入口。画布 340px 高，下面是需求 / 评审 / 版本切换；生成进度和局部编辑位于画布之后、标签之前，任何标签都能看到。生成完成自动选中评审，不自动滚走画布。需求栏生成按钮在栏内贴近底部，底部另有保存状态与演练入口。弹窗高度受视口约束，内部自然滚动。

系统字体栈：`-apple-system, BlinkMacSystemFont, PingFang SC, Microsoft YaHei, sans-serif`，不下载字体。主页标题桌面上限 84px，手机 52px；正文 14–17px；工具状态 12–13px；版本父节点 12px，属于辅助信息。字号不强行套 4px 网格，间距、圆角与内边距遵循 4px 网格。数字编号可用系统等宽字体。

### 间距、圆角的完整嵌套

间距：4 / 8 / 12 / 16 / 20 / 24 / 32 / 48px。圆角均由 CSS token 管理，不为每个组件发明新值。

```text
桌面弹窗 R32，p16
 └─ 内容面板 R16，p8（或布局留白 p16；不在非贴边元素强行共圆心）
     └─ 控件 R8，p4
         └─ 小标签 R4（最小值）
卡片 / 图纸 R24，p8
 └─ 内部操作块 R16，p8
     └─ 控件 R8，p4
         └─ 标签 R4
版本卡片 R16，p8
 └─ 缩略图 R8
主页深色工具条 R16，p8
 └─ 按钮 R8
分段控件 R8，p4
 └─ 选项 R4
手机弹窗 R24，p12
 └─ 内容 R12，p4
     └─ 内控件 R8
```

嵌套且贴边的盒子使用 `r = R − p`；非贴边按钮不以容器全部空白当作嵌套间距。侧栏与整体工作台为平面无圆角布局，避免卡片叠卡片。胶囊状态与头像保持全圆 `999px`。连续曲率通过 `@supports (corner-shape: superellipse(1.25))` 渐进增强，胶囊与圆形覆盖 `round`；不支持时回退普通圆角，不影响操作。

### 动效

按钮背景 140ms，按下移动 1px；版本与评审出现 240ms，位移 8px，曲线 `cubic-bezier(.2,.8,.2,1)`。进度条 240ms。家具参数实时重算，以可见形变回应输入，不做无意义循环漂浮。尊重 `prefers-reduced-motion`：移除动画、过渡与平滑滚动。鉴于本次禁止引入依赖，不增加动效库，也不做强制滚动叙事。

## 两条指定方案的落点

1. **递进式连续圆角**：版本卡片与缩略图、深色工具条与按钮、弹窗与内容面板、分段控件与选项都有可检查的 R / p / r 关系；按上表统一管理。连续曲率只增强外观，不参与布局计算。
2. **ASCII / Dither 参数化家具**：`furniture.js` 先在离屏 Canvas 生成家具，再逐格采样亮度，不贴一层随机噪点。ASCII 用 `. , : ; + = * # % @` 从疏到密映射亮度；主页可调字号、格距（颗粒）、对比强度与暗部 / 亮部。Dither 用 4×4 Bayer 阈值，把亮度量化为 2–6 级并着色；颗粒决定像素块，纹理尺度决定 Bayer 重复尺度，强度越高层级越少。纵向遮罩默认 ASCII 90、Dither 88，底部保留最低可见透明度，不让手机家具消失。工作台提供原形 / Dither / ASCII 快速切换，修改与导出以原形为准。

这里刻意保留像素间隙、扫描式字符与线影，让家具读起来像可重编排的数据，不用照片贴图、实体化旋转展示或颗粒堆砌。

## 八类状态

| 状态 | 画面与可用动作 | 数据处理 |
| --- | --- | --- |
| 空态 | 安静图纸、一个加号、试用圈椅入口 | 不填假历史，不要求登录 |
| 生成中 | 四阶段、解释、停止；可平移缩放 | 锁定会改变任务含义的输入 |
| 部分结果 | 主图先出现，版本标「待评审」 | candidate 只建一次，后补评分 |
| 成功 | 主图、评审、版本与修改动作 | 保存完整版本快照，标记最佳 |
| 失败 | 具体服务原因、次数说明、重试 | 保留输入、旧版本；重试原任务 |
| 已停止 | 显示停止说明，保留已出的图 | 不继续自动轮次，可继续当前稿 |
| 断线 | 明确连接中断，提供恢复 | 保留任务 ID 与阶段，恢复后继续原任务 |
| 刷新恢复 | 提示已恢复原现场，进度接续 | 从 localStorage 读取 phase / candidate，不重建任务 |

底部「状态演练」可逐项触发。每次演练新建独立作品，旧作品仍在作品集；如果正有模拟任务，会停止并保存后再演练。刷新恢复入口执行真实页面刷新。localStorage 不可写时显示保存失败，继续允许操作与导出，不显示虚假已保存。

## 实现边界

所有文件位于 `public/proposals/astra/` 与 `docs/redesign/astra/`。HTML 相对引用 CSS / JS，无 CDN、字体下载、网络模型调用、框架或安装步骤。可直接打开 `index.html`；建议本机静态 HTTP 服务查看，以便跨页面持久化行为一致。只有此提案的 localStorage 命名空间被使用，不读取现有应用数据。

未来后端接线：账号 → `auth/*`；生成与恢复 → `generation-tasks`；单次 / 自动迭代 → `generate` / `agent/run`；会话作品集 → `history`；参考 → `reference-cases`；管理员验证后设置 → `config`。设计会话、分支、选区、锁定记忆与导出版式属于规划能力，原型的数据结构为这些交互保留位置，不宣称后端已支持。

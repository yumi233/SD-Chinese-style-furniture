# 木生 · UI / UX 重新设计需求书

日期：2026-10-31。本文件是四个独立设计方案共同的唯一输入。

## 0. 最重要的一条

**忘掉这个仓库里现有的全部网页设计。** 不要打开、参考或延续 `public/` 下现有页面的布局、配色、组件、文案和交互。从产品需求出发重新思考。现有后端与接口保留，界面和体验完全重做。

目标气质：**年轻化、超前化**的设计工作台。不是传统官网，不是后台管理面板，不是复古中式风格。像一个新一代的创作工具。

## 1. 产品是什么

木生是一个 **AI 家具设计工作台**。用户用一句话描述一件家具，木生生成效果图，用视觉模型按维度评审，再根据评审或用户的修改意见继续迭代，直到满意，最后导出。

- 用户：设计专业学生、年轻家具设计师、小型工作室。手机和电脑都会用。
- 核心价值：从「一次性生图」变成「围绕一件作品持续设计」——能改、能比、能追溯。
- 家具题材：以中式及当代家具为主（椅、桌案、柜、榻等），但界面本身不应显得老气。**不要用老式家具照片做主视觉。**

## 2. 已有能力（后端已实现，界面需要承载）

| 能力 | 说明 |
| --- | --- |
| 账号 | 注册、登录、个人资料；生成和历史需要登录 |
| 单次生成 | 描述 + 风格 + 参数 → 一张或多张效果图 |
| 智能体迭代 | 生成 → 视觉评审打分 → 自动修正描述 → 再生成；目标分（默认 85）与轮数（默认 2，最多 3）可调；返回每一轮和最佳一轮 |
| 评审维度 | 文化准确性、结构合理性、材料工艺、设计创新、场景适配、AI 使用，六项分数与修改建议 |
| 风格起点 | 明式、新中式（当代简约）、宋韵、禅意 |
| 参数 | 画布比例（16:9 720p/1080p、4:3 720p/1080p）、精细度、氛围、约束条件 |
| 提示词 | 中文描述，自动翻译与增强为英文提示词，可查看和编辑 |
| 参考案例 | 内置教学案例，可浏览、匹配 |
| 生成任务 | 后台任务：创建、查询进度、停止；刷新后能恢复 |
| 历史 | 列表、详情、恢复到工作台、删除、下载图片 |
| 重跑 | 同参数重跑、带变化词重跑、回填上一版描述 |
| 模型设置 | 仅管理员可见 |

接口：`/api/v1` 下 `auth/*`、`generate`、`agent/run`、`generation-tasks`（GET/POST、`/:id`、`/:id/stop`）、`history`、`history/:id`、`history/assets/:filename`、`reference-cases`、`health`、`config`（管理员）。原型可用模拟数据，不调用付费接口。

## 3. 规划中、希望界面先想清楚的能力

- **设计会话**：一件作品一条会话，里面有需求、多个版本、对话与评审。
- **版本**：每次生成都是一个版本，可以从任意版本分出新方向，可以两两比较。
- **框选改一处**：在图上框一块区域，说一句修改意见（如「扶手再薄一点」）。精度取决于模型，不承诺像素级。
- **设计记忆**：确认过的属性（材质、比例、禁止改动）可锁定，后续每轮保留。
- **导出**：主图、评分、材质、说明排成一页。

## 4. 必须做好的体验

1. **主页（应用官网）**：一进来就明白木生能做什么，并且**可以上手玩**，不是一屏文字。要有交互感和记忆点。
2. **工作台**：以作品为中心，状态清楚，下一步动作明显。
3. **生成的感觉**：等待过程本身要像在做设计，而不是转圈。进度对应真实阶段（理解需求 → 起稿 → 出图 → 评审），可以停止；失败时说明是否扣次数。
4. **画布的感觉**：像在一张设计图纸上工作——缩放、平移、框选、比较、批注。
5. **评审的表达**：六个维度的分数与建议，清楚且有设计感，分数不压过作品本身。
6. **移动端**：390px 宽度下完整可用，不是桌面版的缩小。
7. 必须覆盖的状态：空态、生成中、部分结果、成功、失败、已停止、断线、刷新恢复。

## 5. 两条必须吸收的设计方案（用户指定）

### 5.1 递进式圆角 + 连续曲率圆角

- 内圆角 = 外圆角 − 间距（r = R − p），内外共用一个圆心。从外到内：对话框/卡片 → 面板、输入框、按钮 → 标签。例：对话框 32、内边距 16 → 内部面板与按钮 16；16 的面板里内边距 8 的标签 → 8。
- 同一层级的盒子共用一个圆角。最小 4px。胶囊和圆形保持全圆。
- 所有内边距、间距、圆角在 4px 网格上。圆角用 token 管理。
- 连续圆角（超椭圆）作为渐进增强：
  `@supports (corner-shape: superellipse(1.25)) { :where(*) { corner-shape: superellipse(1.25); } }`，胶囊与圆形设 `corner-shape: round`。Chrome / Edge 139+ 生效，其余浏览器回退普通圆角。

### 5.2 ASCII 与 Dither 参数化效果

- **ASCII**：把画面切成网格，每格按亮度换成字符，从「.」到「@」越来越密。字号、格距、采样强度（明暗对比）、取样暗部或亮部可调。
- **Dither**：把画面切成像素块，用 4×4 Bayer 矩阵当阈值，把每个颜色压成几级。像素块大小、纹理尺度、采样强度（越高级数越少、颗粒越重）可调。
- 可加一层纵向遮罩，让效果像纹理而不是噪点；推荐值 ASCII 遮罩 90、Dither 遮罩 88。
- 用户的意图：把家具「数码化」。家具可以被拆解、重组，**但不要实体化**——一格一格（像素/字符）或一条一条（切片/扫描线）的感觉。效果必须在手机上清楚可见，不能只是一层几乎看不出的滤镜。

## 6. 约束

- 原生 HTML / CSS / JavaScript，不引入框架和外部 CDN，离线可运行。
- 尊重 `prefers-reduced-motion`；对比度满足 WCAG AA；键盘可操作。
- 遵守项目原则：**Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.** 不堆眉题、副标题和装饰性英文。
- 中文为主，界面文案简短。

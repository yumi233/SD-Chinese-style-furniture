# 模型路由与委派政策

2026-11-19 起按用户要求执行：代码只用最新的 GPT 模型，文字交给 Gemini。不再按“最便宜可靠”逐级升级。

## 分工

| 工作 | 模型 |
| --- | --- |
| 全部实现：前后端代码、测试、脚本、Docker、截图体检、修复 | `gpt-6.2-sol`（最低档，不再往下） |
| 全部审查：每个 PR 的代码、截图、测试结果 | `gpt-6.2-astra` |
| 关键设计、需求澄清、优先级、冲突裁决、最终验收 | `gpt-6.2-astra` |
| 面向人的文字：界面文案（简/繁/EN）、参考案例文字、文档与报告正文 | 最新 Gemini Pro（`gemini-pro-latest`），不可用时用版本号最高的 Gemini Flash |

不使用 Luna、Terra 和更早版本的 Sol/Astra。Gemini 不写代码、不做审查；它写的文字随 PR 一起由 Astra 审查。

## 模型核对

- 每次派活前从当次模型列表确认目标模型存在；不存在就停下报告，不静默换成其他模型。
- 每份交付必须写明实际调用的模型 ID；不是指定模型的交付退回重做。
- Gemini 的 base URL、密钥规则不变：凭据只来自宿主环境，绝不写入文件、日志、回复或提交。

## 委派协议

遵循“拆解 → 委派 → 审查 → 修改 → 验收”。实现与审查不由同一模型完成。每个子任务返回七项：已完成工作、文件、关键改动、测试命令、测试结果、未解决问题、风险。

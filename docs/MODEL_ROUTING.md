# 模型路由与委派政策

目标是用可靠性足够的最低成本模型和最低必要推理强度。默认升级顺序为：动态 Gemini Flash → Luna → Terra → Sol → GPT-6 Astra；也可按复杂度直接选择。调用前核对宿主是否已注册；未注册回退 Luna。本规则不自动安装或注册工具，也不证明凭据已配置。

## Gemini Flash worker

`gemini_flash` 是外部 worker/MCP 调用自托管 OpenAI-compatible API 的约定。主机提供 `GEMINI_PROXY_BASE_URL` 与 `GEMINI_PROXY_API_KEY`；密钥绝不写入文件、日志、回复或提交。单凭 `chat/completions` 不获得文件系统或 shell 能力；仅使用实际注册的能力，否则由主机提供上下文并应用、审查和测试结果。worker 能力以宿主注册为准，不能断言其永远只返回建议。

每次调用先把 base URL 规范化，再请求 `/models`（通常为 `/v1/models`，避免重复 `/v1`）。从返回模型中筛选名称含 `flash`（不区分大小写）的 Gemini 模型；多个候选时，只在已有信息支持的情况下偏好已知更新或更强的轻量版本，不能仅凭任意排序猜测版本或能力。没有 Flash 时，若已知适配性，可选可用的轻量 Gemini。不得硬编码历史模型 ID。使用实际选定 ID POST `/chat/completions`，采用该模型支持的最低必要 reasoning。若工具缺失、API 不可用、列表失败、无合适候选或调用失败，回退 Luna；重试必须有界，禁止无休止试错。仅在有助于诊断时记录实际模型和回退原因，绝不记录密钥、请求头或 token。

## 分层路由

- **Gemini Flash（L1）**：目标清晰、低风险、验收明确的搜索结果分析、代码/文件读取、日志、docs/README/Markdown/JSON/YAML、简单 HTML/CSS/代码、明确方案实施、测试摘要，以及批量文本、格式、静态或重复工作。
- **Luna**：Gemini 不可用、不兼容、失败、理解不足，或上下文连续性使 Luna 更可靠时回退。两者不负责架构判断。
- **Terra（L2）**：常规功能、前端/API/Node/Docker/Compose/Windows 脚本、一般缺陷、重构、测试和中等复杂度多文件逻辑；通常负责实施 Astra 的方案。
- **Sol（L3）**：跨模块重构、困难缺陷、并发、安全、状态/数据问题、API 架构迁移，或 Terra 重复失败。
- **GPT-6 Astra（L4）**：需求澄清、复杂分析、架构与权衡、规划/路由、风险、冲突解决、关键审查和最终验收，避免机械工作。

不要把架构、危险安全变更、复杂跨模块或状态问题、含糊需求、重大权衡、最终验收或冲突解决交给 Gemini。失败按上述顺序升级，明显无能力的模型不重复尝试。

## 委派协议

遵循“思考→拆解→最低可靠模型→委派→汇总→检查 diff 与测试→验收”。避免重复全仓扫描。每个子任务返回七项：已完成工作、文件、关键改动、测试命令、测试结果、未解决问题、风险。规则本身不实现 worker。
`gemini_flash` 本地执行 worker 按用户最新偏好，每次动态发现后选择数字版本最高的 Gemini Flash 文本模型；例如 3.8 可用时用 3.8，3.9 出现后自动用 3.9。此规则覆盖前文通用低成本选择策略。
